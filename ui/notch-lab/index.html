The idea

Decision & scope

Password entry is a mock: typing inserts a fixed demo value. Verify simulates approval; no Mac password is read or checked.

Source notes & native implementation boundary

Informed by Clavis US-02 (app, key, operation), US-49 (policy-permitted fallback), US-72/73 (name detected agents), D-28 (sessions bound to requesting app and key), and the existing Touch ID prototypes. These are layout studies; changing the duration here does not change a key policy. All scopes end on lock, sleep, restart, or manual clearing. A stricter key policy must hide or disable unavailable choices.

In the native app, the biometric area must use Apple’s system-owned LAAuthenticationView or the appropriate LocalAuthenticationView. This HTML uses a fingerprint illustration to indicate its reserved area. Password fallback expands an inline drawer. Its field substitutes a fixed demo value for typing or paste; Verify simulates approval. No Mac password is read or checked. The camera stays dark: authentication does not imply camera use. CSS motion/materials approximate the intended behavior; they do not verify native rendering or Apple compliance.

Keyboard: Tab into the prompt to restore its controls. Escape denies the request. Focus leaving the prompt collapses session and action controls without changing the selected duration or confirming anything. OS reduced-motion settings suppress transitions.
